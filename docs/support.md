# Support and security reports

Before opening a report, collect `career version --json`, the redacted output of `career doctor --json`, operating system, Python version, and the exact command that failed. Use synthetic data to reproduce the problem. Never attach a real resume, application answers, credentials, workspace archive, browser session, or raw journal containing personal data.

Use the repository issue tracker for ordinary bugs and feature requests. Mark security reports as private through the GitHub repository's security-reporting channel once enabled. Until that channel is configured, do not publish vulnerability details; contact the repository owner privately.

This early-access project offers no uptime or response-time guarantee. Real employer portals and irreversible submissions are outside ordinary automated support reproduction.
